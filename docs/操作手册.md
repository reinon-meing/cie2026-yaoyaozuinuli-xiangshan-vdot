# 操作手册：从仓库复现 vdot.vv

> 面向对象：从 GitHub 下载本作品、想在自己的 Ubuntu 机器上复现结果的人（评委/同学）。
> 本手册不依赖作者的服务器 IP、用户名或 `~/xs-env` 绝对路径，所有路径都用环境变量表示。
> 配套：[作品文档.md](作品文档.md)（语义、实现、数据、结论）。
> 下文用 `<仓库路径>` 表示你 clone 下来的本作品仓库根目录，例如 `/home/you/xiangshan-vdot`；请按实际路径替换。

## 3. 获取源码

```bash
# 三个仓库放在同一工作根下，后面用环境变量引用
export XS_ROOT=$HOME/xs-env
mkdir -p $XS_ROOT && cd $XS_ROOT

git clone https://github.com/OpenXiangShan/XiangShan.git
cd XiangShan && git checkout 16ae9ddcd && git submodule update --init --recursive
cd $XS_ROOT

git clone https://github.com/OpenXiangShan/NEMU.git
cd NEMU && git checkout a48a11f2
cd $XS_ROOT

git clone https://github.com/OpenXiangShan/nexus-am.git
cd nexus-am && git checkout 086a2380

# 环境变量（也可以用仓库自带的 env.sh）
export NOOP_HOME=$XS_ROOT/XiangShan
export NEMU_HOME=$XS_ROOT/NEMU
export AM_HOME=$XS_ROOT/nexus-am
```

> 提示：XiangShan 在 detached HEAD 上工作，`git checkout` 后不要随意切换分支。

## 4. 应用补丁

```bash
cd $NOOP_HOME
git apply --check <仓库路径>/patches/01-xiangshan-vdot.patch
git apply         <仓库路径>/patches/01-xiangshan-vdot.patch
git diff --stat    # 预期：2 files changed, 36 insertions(+), 4 deletions(-)

cd $NEMU_HOME
git apply --check <仓库路径>/patches/02-nemu-vdot.patch
git apply         <仓库路径>/patches/02-nemu-vdot.patch
git diff --stat    # 预期：3 files changed, 32 insertions(+), 1 deletion(-)
```

## 5. 构建功能 emu（difftest 用）

```bash
cd $NOOP_HOME
rm -f build/emu-compile/VSimTop.mk      # 改过构建参数后必须删，否则 make 会秒退
make emu CONFIG=MinimalConfig VEXTRA_FLAGS="-Wno-UNOPTFLAT" -j$(nproc)
# 产物：build/emu（约 40–70 分钟）
```

要点：

- `VEXTRA_FLAGS` 必须写在 **make 命令行**上。这样它会覆盖 makefile 里的追加参数，等价于屏蔽
  `+define+VERILATOR_LEGACY` 等宏——这是 difftest 能正常工作的关键（见第 11 节）。
- `-Wno-UNOPTFLAT` 是香山门控时钟 SRAM 的固有告警，不加会被 Verilator 当致命错误。

## 6. 构建波形 emu（可选，仅 dump 波形用）

```bash
cd $NOOP_HOME
cp -p build/emu build/emu-diff        # 保留功能版
rm -f build/emu-compile/VSimTop.mk
make emu CONFIG=MinimalConfig VEXTRA_FLAGS="-Wno-UNOPTFLAT --trace" -j$(nproc)
cp -p build/emu build/emu-wave
```

- `--trace` 直接在 `VEXTRA_FLAGS` 里显式给出，同样避免 makefile 追加 `VERILATOR_LEGACY`；
- 验证 trace 是否编进去：`strings build/emu-wave | grep -c VerilatedVcd`（应远大于 0）；
- 本作品验证过的组合是：**功能/difftest 用 `emu-diff`，波形用 `emu-wave --no-diff`**。
  若你想用同一个二进制同时做两件事，请自己用 `--diff` 验证一次（本作品未把该组合列为保证项）。

## 7. 构建 NEMU 参考模型

```bash
cd $NEMU_HOME
make riscv64-xs-ref_defconfig
make -j$(nproc)
# 产物：build/riscv64-nemu-interpreter-so（分钟级）
```

> 该参考模型只用于 difftest，不替代 `ready-to-run/` 下的官方模型；跑本作品测试时请显式指定它。

## 8. 构建测试程序

把仓库 `scripts/` 下各 app 目录拷进 nexus-am，然后编译（秒级）：

```bash
cp -r <仓库路径>/scripts/vdottest      $AM_HOME/apps/
cp -r <仓库路径>/scripts/vdot_sew_test $AM_HOME/apps/
cp -r <仓库路径>/scripts/vdot_edge_test $AM_HOME/apps/
cp -r <仓库路径>/scripts/vdot_wave     $AM_HOME/apps/
cp -r <仓库路径>/scripts/vdot_latbench $AM_HOME/apps/
cp -r <仓库路径>/scripts/base_latbench $AM_HOME/apps/
cp -r <仓库路径>/scripts/loop_latbench $AM_HOME/apps/

for app in vdottest vdot_sew_test vdot_edge_test vdot_wave vdot_latbench base_latbench loop_latbench; do
  (cd $AM_HOME/apps/$app && make ARCH=riscv64-xs CROSS_COMPILE=riscv64-linux-gnu- MARCH=rv64gcv)
done
```

两个坑：AM 默认 MARCH 不含 V 扩展，必须加 `MARCH=rv64gcv`；程序里要先把 `mstatus.VS` 打开。

## 9. 运行测试（全部带 difftest）

```bash
cd $NOOP_HOME
REF=$NEMU_HOME/build/riscv64-nemu-interpreter-so

# 1) 功能 11 例（4–6 分钟）
timeout 600 ./build/emu-diff -i $AM_HOME/apps/vdottest/build/vdottest-riscv64-xs.bin \
  --diff $REF 2>&1 | grep --line-buffered -av PERF
# 预期：VDOT RESULT: 11/11 PASSED

# 2) SEW 5 例（1–3 分钟）
timeout 300 ./build/emu-diff -i $AM_HOME/apps/vdot_sew_test/build/vdot_sew_test-riscv64-xs.bin \
  --diff $REF 2>&1 | grep --line-buffered -av PERF
# 预期：VDOT SEW RESULT: 5/5 PASSED

# 3) 边界 4 例（1–3 分钟）
timeout 300 ./build/emu-diff -i $AM_HOME/apps/vdot_edge_test/build/vdot_edge_test-riscv64-xs.bin \
  --diff $REF 2>&1 | grep --line-buffered -av PERF
# 预期：VDOT EDGE DONE

# 4) 性能微基准（几秒一条）
timeout 90 ./build/emu-diff -i $AM_HOME/apps/vdot_latbench/build/vdot_latbench-riscv64-xs.bin --no-diff 2>&1 | grep -a --line-buffered BENCH
timeout 90 ./build/emu-diff -i $AM_HOME/apps/base_latbench/build/base_latbench-riscv64-xs.bin --no-diff 2>&1 | grep -a --line-buffered BENCH
timeout 90 ./build/emu-diff -i $AM_HOME/apps/loop_latbench/build/loop_latbench-riscv64-xs.bin --no-diff 2>&1 | grep -a --line-buffered BENCH
# 预期：608/613、1119/1210、501/411
```

> **判读**：AM 的 `_halt` 打印 `Exit with code = 0` 后会 `while(1)`，emu 不会自己退出，
> `timeout` 返回 124 属正常；看到 `PASSED`/`BENCH DONE` 即可 `Ctrl-C`。

## 10. 波形复现

```bash
cd $NOOP_HOME
# 全窗口 dump（约 1 分钟，1.9 GB；只有 emu-wave 支持）
timeout 900 ./build/emu-wave -i $AM_HOME/apps/vdot_wave/build/vdot_wave-riscv64-xs.bin \
  --no-diff --dump-wave --wave-path build/vdot_s3_full.vcd -b 1 -e 12000

# 抽 VIAluFix 信号 + 切 2540–2570（几十 KB）
python3 <仓库路径>/scripts/vcd_mini.py build/vdot_s3_full.vcd VialuFix build/vdot_mini.vcd
python3 <仓库路径>/scripts/vcd_slice.py build/vdot_mini.vcd 2540 2570 build/vdot_2556.vcd
```

用 Surfer/GTKWave 打开 `build/vdot_2556.vcd`，展开
`exus_2.VialuFix`，看 5 个信号：`io_in_valid`、`io_in_bits_ctrlPipe_1_fuOpType`（2556 为 0x077）、
`io_in_bits_ctrlPipe_1_pdest`（0x33）、`io_out_valid`、`io_out_bits_res_data`（0x…78 = 120）。

## 11. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| difftest 在 `pc=0x10000004` 报 `t0 different` | 构建时 makefile 追加了 `+define+VERILATOR_LEGACY`（trace 构建常见） | 用第 5 节的命令行 `VEXTRA_FLAGS` 方式重建；不要用 `EMU_TRACE=1` 环境变量 |
| `make emu` 秒退、emu 没变化 | 改了参数但 `VSimTop.mk` 还在 | `rm -f build/emu-compile/VSimTop.mk` 后重跑 |
| 向量指令 double trap / 99 条指令就挂 | `mstatus.VS` 为 Off | 程序开头 `csrrs mstatus, 0x600` |
| 编译报 `vsetivli` 不认识 | MARCH 不含 V | 加 `MARCH=rv64gcv` |
| `timeout` 返回 124 | emu 在 `_halt` 的空转里被截断 | 正常，看日志里的 `PASSED` |
| `--diff ready-to-run/…so` 报非法指令 | 官方模型不认识 vdot | 必须用第 7 节自建的 `riscv64-nemu-interpreter-so` |
